## 1.3 控制模型（理解这个才能改）

`VehiclePhysics.UpdateAir` 里玩家操控的链路：

```
鼠标移动
  ↓ GetAxis("Mouse X/Y") × airMouseSensitivity(0.5)
  ↓ 累加到虚拟摇杆 _airAimX / _airAimY，夹在 [-1, 1]
  ↓ 每帧衰减：MoveTowards(aim, 0, airRecenterSpeed × dt)
  ↓
俯仰角速度 = _airAimY × airPitchRate(70)      °/s
偏航角速度 = _airAimX × airYawRate(50)        °/s
滚转角速度 = A/D键    × airRollRate(140)      °/s
偏航角速度 += sin(侧倾) × airBankTurnRate(42)  °/s   ← 压杆带出转弯
  ↓
用四元数把角速度积分到 transform.rotation
  ↓
松开 A/D 且倾角 < airAutoLevelMaxBank(70) 时，自动把机翼摆平
```

**注意：这是一个"鼠标 = 角速度"的模型，不是"鼠标 = 姿态"。**
鼠标不动 → 摇杆衰减到 0 → 停止转动。想持续转就必须持续推鼠标。

## 1.4 用数值算手感（改参数前先算）

鼠标推满到 1.0 后松手，累计转过多少度：

```
累计角度 ≈ (aim²) / (2 × recenter) × pitchRate

recenter=0.5 → 1/(2×0.5)×70 = 70°   （实测 86°，因为推的过程也在涨）
recenter=1.2 → 1/(2×1.2)×70 = 29°
recenter=3.5 → 1/(2×3.5)×70 = 10°
```

**但"累计角度小"不等于"手感好"** —— recenter 太大就做不了筋斗。
筋斗要 360°，按 70°/s 需要**持续** 5 秒满舵。recenter 必须小到"持续推鼠标能维持接近满舵"，
又不能小到"松手后还在转半天"。**这两个需求是矛盾的**，见 §3 的模型选择。

## 问题 2：操控模型想要哪种？

现在是「鼠标 = 角速度，松手回中」。三种可选：

| 方案 | 手感 | 优点 | 缺点 |
|---|---|---|---|
| **A（现在）** | 鼠标推得越久转得越多，松手慢慢停 | 简单 | 精确和持续转向天然矛盾 |

## 5.1 真正的 bug（在 `VehiclePhysics` 自动改平里）

```csharp
// 旧代码
float tilt = Vector3.Angle(transform.up, Vector3.up);   // ← 俯仰 + 侧倾的合成角！
if (tilt > 0.4f && tilt < airAutoLevelMaxBank)          // 上限 70
{
    // 自动改平
}
```

`Vector3.Angle(up, worldUp)` **不是侧倾角，是俯仰和侧倾的合成角**。
空战里飞机经常抬头 60~80° 爬升，这时 `tilt` 早就超过 70 ——
**自动改平直接失效，之前攒下的侧倾就永远留着。**

这就是"飞机模型总是歪着"的根因，和相机、和鼠标灵敏度都**无关**。

## 5.2 修法

```csharp
// 新代码：只测绕机身前轴的真实侧倾（把机头投影掉）
Vector3 fwdAxis = transform.forward;
Vector3 refUpAxis = Vector3.ProjectOnPlane(Vector3.up, fwdAxis);
if (refUpAxis.sqrMagnitude > 0.01f)
{
    refUpAxis.Normalize();
    float bankAngle = Vector3.SignedAngle(refUpAxis, transform.up, fwdAxis);
    if (Mathf.Abs(bankAngle) > 0.5f && Mathf.Abs(bankAngle) < airAutoLevelMaxBank)
    {
        var level = Quaternion.LookRotation(fwdAxis, refUpAxis);
        float autoK = 1f - Mathf.Exp(-airAutoLevelRate * dt);
        transform.rotation = Quaternion.Slerp(transform.rotation, level, autoK);
    }
}
```

## 5.3 实测验证（决定性）

```
初始姿态：抬头 75° + 侧倾 35°
  旧代码判据 tilt = Angle(up, worldUp) = 77.8°  >  上限 70
  → 旧代码：自动改平失效，侧倾永远留着
  → 新代码：只看真实侧倾 35°，在上限内，正常改平

2 秒后：真实侧倾 = 0.5°   ✅ 已摆平
        Angle(up,worldUp) = 75°（纯俯仰，不是歪）
```

**同一时刻 `Angle(up,worldUp)=75°` 而真实侧倾只有 0.5°** —— 这一组数字直接证明了
旧判据把俯仰当成了侧倾。
