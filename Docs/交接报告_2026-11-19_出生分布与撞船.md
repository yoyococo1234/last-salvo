### 1.1 算法口径

| 规则 | 实现 | 位置 |
|---|---|---|
| **按载具类型独立编号** | `SpawnLane(u, domain, defId)`：只统计"同队 + 同域 + **同 prefId**"的单位 | `MatchManager.SpawnLane` |

| 不落海 / 不落陡坡 | 坡度上限**按载具**：轻坦 33° / 主战 28° / 重装 20° | 同上 |
| 只在真正站得住的 z 段铺 | `UsableSpans()` 先扫出可用段，再把槽位映射到**可用总长**上 | 同上 |

### 1.3 三个真 bug（这轮查出来的）

| # | bug | 根因 |
|---|---|---|
| 1 | **坦克生在海里** | 搜索失败后的兜底是 `best = Clamp(xWant), zWant`，**完全不校验地形**。而 z > 约 430 那一段整片是深水（实测 `(-200,806)` 地形高度 **−81 m**、水深 85 m），220 m 内找不到合法点就直接塞进去 |
| 2 | **可用段被砍掉一半** | 可用段判定只按 `x = 出生线` 单点采样。山脚段（出生线正好压在陡壁上、往里 200 m 就是平地）被误判成"不可用" → 单位全挤在中间 620 m |
| 3 | **重装挤在边界上** | 原来是"按全线算完再 `Clamp` 到 ±320"，钳完之后有三台全卡在 −320 这一条线上 |

修法：兜底改成**沿 z 逐步扫到最近的合法陆地**；可用段横向采 6 个点（0/110/220/330/440/550 m）任一点可用即算可用；重装改成**直接把槽位映射进城区段**。

## 2.1 ✅ 已修：炮艇没有铺开（2026-11-19 11:15 修 + 复测）

满编开局 12 条船（双方各 6）**修之前全挤在 z=937 / 967 两排**（`zMax = 967`，等于贴着地图北边界），
x 只有 3 个值（出生线 3 排），舰队完全没有沿海南北铺开。

根因是**参数语义错位**，`MatchManager.cs:970`：

```csharp
if (domain == Domain.Sea) return FindSeaSpawn(xWant, zWant, zMin, zMax, u.index);
//                                              ^^^^^ 传的是 zWant（米，如 -769~121）
// 而签名是 FindSeaSpawn(float lineX, float lane, float zMin, float zMax, int slot)
//                                 ^^^^ lane 期望 0~1
```

`FindSeaSpawn` 第一行 `float zWant = Mathf.Lerp(zMin, zMax, lane);` —— `Mathf.Lerp` 会把 t **钳到 [0,1]**，
所以 zWant 是正数的船全拿到 `zMax(967)`、负数的拿到 `zMin(-967)`（那边是陆地，第一段循环全失败，
掉到"全图找最远水域"的第二段，又都落到北边界）。

**修法（已实施，1 行）**：

```csharp
if (domain == Domain.Sea)
    return FindSeaSpawn(xWant, Mathf.InverseLerp(zMin, zMax, zWant), zMin, zMax, u.index);
```

**修后复测（满编，编辑器 Play，未 Begin 时读的真实出生点）**：

```

修后 team0 船 z = 860 / 773 / 686 / 600 / 513 / 426     间距 86.8 m，跨度 434 m
     水深 25.6 ~ 93.8 m 全部合规（<2.5 m 的 0 条），x 仍是 -640/-600/-560 三排
team1 完全镜像；陆战 + 飞机 48 台的出生点逐项不变（主战 121/-58/-237/-417/-596/-769，无回归）
```

## 2. 舰船撞船（整套逻辑从没跑过）

用户："舰艇和对面的舰艇碰撞有问题，应该是我和对面碰撞扣一些血，碰己方弹开，这个功能我们做过"

`VehicleCollision` 里**敌方扣血 + 弹开、队友只弹开不扣血**的代码 2026-11-05 就写好了，
但从来没生效过：

```csharp
void Awake() { _col = GetComponent<Collider>(); }        // ← 这时是 null
void Update() { if (... || _col == null) return; }       // ← 第一行就退出
```

根节点的 `BoxCollider` 不是预制体自带的，而是 `VehicleCombat.EnsureHitCollider()` 在
**`Start()`** 里 `AddComponent<BoxCollider>()` 现建的（它自己的注释就写着"`Awake` 时
`GetComponentsInChildren<MeshFilter>()` 拿不到网格会静默失败"）。`Awake` 比 `Start` 早 → `_col` 恒 null。

**修**：懒加载（每帧补一次，拿到就缓存）。

附带修一条：原来 `if (rel < ramMinSpeed) return;` **挡在弹开之前**，所以"慢速蹭一下队友"
既不扣血也不弹开，两辆车贴着走。现在速度阈值只管**扣血**，弹开无条件执行（慢速也给最小冲量）。

**验证技巧**（重要）：别用"血量变化"判断撞船 —— AI 一直在互射，血本来就掉。
用 `VehicleCollision._nextDamage`：**只有碰撞扣血才会写它**，`nextDmg ≈ now + 1.2` 就是刚撞过。

```
实测: _col = 已拿到；rel = 32（阈值 8）；敌船 nextDmg=52.49 而 now=54.29 → 3 秒前刚撞过
```

**2026-11-19 11:14 复验（更严格的做法，结论：全部通过）**

上一轮的实测有个隐患：60 台 AI 同时在跑，**别的车会自己撞上来**污染判据。这次改成：
全场 `VehicleAI.enabled = false`、只留两条船、其余挪走、把 `Time.timeScale` 压到 0.15（慢动作，
避免 MCP 往返十几秒里两条船开出几百米），并用反射把 `_next` / `_nextDamage` 清零后重测。

```
_col = 60/60 全部拿到（BoxCollider 18.0×5.2×3.8）

敌方撞我方（相对速度 40 m/s）：
  我方 4500 → 4463（-37），敌方 4500 → 4433（-67）        ← 双方都掉血 ✓
  处理方 _nextDamage = 62.40，now = 62.83                ← 1.2 s 冷却在走 ✓
  两船距离 2.00 m → 14.66 m                               ← 被弹开 ✓

友军对撞：
  双方 hp 一点没掉（4463 / 752 → 不变），_nextDamage 双方都是 0   ← 不扣血 ✓
  距离 3.00 m → 25.99 m                                          ← 照样弹开 ✓
```

> 坑：`Time.timeScale=1` 时"sleep 2 秒"实际跨越十几秒游戏时间（MCP 往返 + 编辑器自身耗时），
> 两条船能开出 300 m 以上，读数完全对不上。要么压 `timeScale`，要么在**同一次**脚本调用里读完。
