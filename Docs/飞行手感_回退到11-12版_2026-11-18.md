## 2. 修的两个真 bug（这才是"横向反转"的来源）

### ① 「压杆带出转弯」是死代码 —— 从来没生效过

```csharp
// 旧：up 和 right 是同一个正交基里的两个轴，点积恒等于 0
float bankSin = Vector3.Dot(transform.up, transform.right);
```

MCP 实测 `dotUpRight = 0.000000`，**任何姿态都是 0**。
所以压坡度完全不转弯，飞机只能靠鼠标左右偏航拐弯 ——
空战里 90% 的转弯本该来自压杆，全丢了，手感自然是"像在轨道上飞"。

```csharp
// 新：机身 up 在「水平右方向」上的投影 = sin(坡度)
Vector3 rightHoriz = Vector3.Cross(Vector3.up, transform.forward);
float bankSin = rightHoriz.sqrMagnitude > 0.0001f
    ? Vector3.Dot(transform.up, rightHoriz.normalized) : 0f;
```

实测：45° 右坡度 → `bankSin=0.71`、偏航 **+29.9°/s**（=0.71×42），右压杆右转弯 ✅

### ② 转弯时相机自己在转（6°/秒匀速自转）

11-17 那版把"飞机 up 投影到视线垂直面"再求帧间夹角当滚转增量。
**投影平面自己在转**（视线随偏航/俯仰变），所以纯转弯也会算出滚转：

- 平飞只推偏航 20° → 相机自己歪 **-0.77°**
- 45° 坡度盘旋 → 相机 **-6.0°/秒匀速自转**（`dot(worldUp, lookDir) = -0.22` 的泄漏）

累积到 `_camRollFollow` 上就是"画面自己慢慢歪/横向反转"。

**改法**：扭转量绕**机头轴**（`target.forward`）取，不再绕视线 ——
平飞/带坡度平飞时 `dot(worldUp, forward) ≡ 0`，转弯完全不漏。

## 4.7 当天下午追加 3：相机"越飞越歪"真因 + 取消前后空翻（用户第四次反馈）

用户发截图：**仪表显示「俯仰 -1° 坡度 0°」，画面里地平线却斜了 30°**，并说
**"你觉得这是对的吗，应该飞机是平的，我们干脆不要前后翻滚功能了，只要左右翻滚吧"**。

### ① 相机越飞越歪 —— 是我上一版（4.6 之前）留下的真 bug

上一版用「四元数旋转增量在**机头轴**上的分量」当滚转增量。**这个量不等于机身滚转**：

> 机头仰起 30° 时绕世界竖轴偏航 10°，增量在机头轴上的分量 = 10° × sin30° = **5°**，
> 但真实坡度变化是 **0°**（MCP 算过：偏航前后 `SignedAngle(refUp, up, forward)` 都是 0）。

于是**每转一个弯就偷偷攒几度**，飞几分钟就是 30° —— 仪表说 0°、画面歪 30°，用户看到的正是这个。

**改法**：不再从增量反推，直接跟踪**真实坡度角**，用"展开（unwrap）"消掉 ±180 歧义：

```csharp
float raw  = Vector3.SignedAngle(refUpAxis, planeUp, fwdAxis);   // -180~180，瞬时量
_bankCont += Mathf.DeltaAngle(_bankCont, raw);                    // 连续值，滚多少圈都不断
_camRollFollow = _bankCont * airRollFollow;
```

真实坡度对偏航/俯仰免疫，所以这条链路**既不漂、也没有 180° 跳变**。

**实测**（MCP，Unity Play）：

| 场景 | 结果 |
|---|---|
| 仰头 30° 连续转弯 3 秒 | 相机滚转 **0.0°**（改前会一路攒歪）✅ |
| 40° 坡度 | 相机 -34.0°，跟随比 **0.85** ✅ |
| 带坡度转弯 2.5 秒 | 相机漂移 **0.00°**（改前 -6°/s）✅ |
| 连续滚满 360°（桶滚） | `bankCont=-400`、单步最大变化 17°，连续无跳变 ✅ |

### ② 取消前后空翻，只保留左右桶滚

用户要求。做法：给俯仰加**硬限位** `airMaxPitchDeg = 70`（新字段）——
能爬到 70°、俯冲到 -70°，但**不能翻过顶**；左右滚转仍然 360° 自由。

实现要点：算出"这一帧本来要俯仰到的角度"，超限就**把增量截断**（不是往反方向掰），
所以贴着限位继续推鼠标只是停住，不会弹。**实测：一直推鼠标抬头，俯仰停在 70°** ✅

## 4.8 当天下午追加 4：滚几圈之后飞机歪 —— `airRollFollow` 必须是 1.0（用户第五次反馈）

用户："为什么转了很多圈，进行了一些操作之后，**飞机歪斜了**，理论上它应该与电脑边框永远平行"。

**根因：比例小于 1 必然留残差，不是漂移。**

```
camRoll = airRollFollow × 累计滚转角
```

完整滚一圈（360°）之后飞机已经回到平飞（坡度 0），但相机被留在
`0.85 × 360 = 306° ≡ -54°`。MCP 实测：

| 场景 | 坡度（真实） | 相机滚转 | 结果 |
|---|---|---|---|
| 滚满一圈（0.85） | **0°** | **+54°** | 飞机在画面里歪 54°，仪表却说 0° ← 用户看到的 |
| 滚满一圈（**1.0**） | 0° | **0.00°** | ✅ |
| 滚三圈（1080°，1.0） | 0° | **0.00°** | ✅ 滚多少圈都精确回正 |

滚两圈歪 108°，滚得越多越歪 —— 这就是"转了很多圈之后歪了"。

**改法：`airRollFollow` 0.85 → 1.0**（场景里序列化的值也改了，`Map_Battlefield.unity` 第 64349 行）。
1.0 正好是用户要的观感：**飞机永远正着、平行于屏幕边框，歪的是环境（地平线）**。
应用角度收进 ±180（`Mathf.Repeat`）只是防浮点越滚越大，`AngleAxis` 对 ±360 完全等价。

⚠️ **不要再把它调回 0.85 之类的小数** —— 那不是"柔和一点"，那是每滚一圈就攒 54° 的歪。

2. **`airRecenterSpeed` 别超过 0.8** —— 超过就按不住鼠标、做不出筋斗（11-17 从 3.5 一路退回来）。

   想让"松手自己摆平"更慢就把速率降到 1.5~2.0；想留更多特技空间就把上限降到 60。
   ⚠️ 但**不要**在没修判据的情况下动这两个值 —— 旧判据（`Angle(up, worldUp)` 当侧倾角）
   在抬头爬升时恒 >70°，会让自动改平完全失效，那才是 11-17「怎么调都不回正」的真因。
4. 用 MCP 量手感的三个正确指标：
   ```csharp
   // 坡度（正负只表示左右，取绝对值）
   float pb = Vector3.SignedAngle(Vector3.ProjectOnPlane(Vector3.up, t.forward).normalized, t.up, t.forward);
   // 相机滚转（必须用"投影到视线平面"再求角，直接 Angle(cam.up, Vector3.up) 量的是俯角！）
   float cr = Vector3.SignedAngle(Vector3.ProjectOnPlane(Vector3.up, cam.forward).normalized, cam.up, cam.forward);
   // 相机是否在"自己转"：同一坡度下 cr 随时间的导数应 ≈ 0
   ```
5. **Play 模式下 `Time.timeScale` 可能是 0**（开始封面没点开始）——
   这时飞机物理**不跑**（`Time.deltaTime=0`），但相机用 `unscaledDeltaTime` **照跑**，
   测出来的数据会一半真一半假。测之前先 `GameStartScreen.Begin()` + `Time.timeScale=1`。
