## 1. 现在代码是怎么做的（`WingStores.BuildProps`）

```csharp
// 只在飞机根节点的局部空间摆弹，x=右 y=上 z=前，localRotation=identity
float spanWorld = 世界翼展（米，从网格 bounds × lossyScale 取最长边）
float s = 根节点 lossyScale 的标量
float L = missileLenWorld / s;                    // 弹长（本地单位）
float halfSpanLocal = (spanWorld * 0.5f) / s;
float downOffset = (弹径 * 1.35f) / s;

// 单发 → 机腹中线
localPos = new Vector3(0f, -downOffset, 0f);
// 多发 → 机翼下
localPos = new Vector3(side * halfSpanLocal * t, -downOffset, 0f);   // t = 0.42~0.82
```

**已知不足（下一任从这儿接着做）：**

1. **`downOffset` 只是"弹径 × 1.35"，不是真实的机翼下表面高度。**
   所以弹体要么陷进机翼、要么悬空 —— 用户说的"差一点点/差很多"很可能就是这个。
   **正确做法：求出该翼展位置的机翼下表面真实高度**，让弹顶贴着它。

2. **`halfSpanLocal * t` 是拍的比例，不是真实翼展位置。**
   攻击机的机身很宽（翼根部分），0.42 可能还在机身里。

3. **没有做"挂架连到机翼"的视觉连接。**
   现在的挂架是固定比例的小方块，不保证真的碰到机翼。

## 2. 🔴 下一任必须先知道的事实

### 两种飞机模型尺度差 100 倍（MCP 实测）

| | 攻击机 `air_attacker` | 战斗机 `air_fighter` |
|---|---|---|
| 网格 bounds size | **17.60 × 17.53 × 5.59**（真实米） | **0.09 × 0.11 × 0.05**（厘米级） |
| Model 节点 lossyScale | **0.60** | **100.00** |
| Model 节点 rotation | (270.02, 90.00, 0) | (270.00, 270.00, 0) |
| Model 节点 localPosition | **(0, 1.68, 0)** | (0, 0, 0) |
| 世界翼展 | 10.56 m | 10.57 m |

**世界翼展几乎一样，但网格空间差 100 倍。**
任何写死的米数常数（如 `-0.18f`）在战斗机上会被放大成 **18 米**。

### 轴向映射（模型 rotation 决定的，别想当然）

攻击机 `rotation=(270,90,0)`：
- 网格 +X → 世界 **-Z**
- 网格 +Y → 世界 **-X**
- 网格 +Z → 世界 **+Y（上方）**

战斗机 `rotation=(270,270,0)`：**又不一样**。

**所以千万不要在网格空间算坐标再 `TransformPoint`。**

## 4. 我这一天的错误清单（供下任避雷）

### 错误 1：改错对象
用户说"空空导弹"，我一直在改**攻击机**的反坦克导弹。
两个机型共用 `WingStores`，但配置不同（`ammoCapacity` 8 vs 1）。
**教训：先确认用户说的是哪个型号。**

### 错误 2：拿网格局部坐标当世界坐标验证
我用 `InverseTransformPoint` 反算局部坐标判断"在下方"，报了一堆 **假"✅"**。
换成 `Vector3.Dot(rel, plane.transform.up)` 一测，8 枚弹的 up 分量全是 **+1.12~+1.51**，全在飞机上方。
**教训：验证几何位置必须用世界坐标 + 目标自身轴。**

### 错误 3：写死米数常数
`bestZ - 0.18f` 当"往下 18 厘米"。攻击机上对，战斗机上变成 18 米。
**教训：跨模型操作，所有长度从"世界尺寸"取标量再除以 lossyScale。**

### 错误 4：在网格空间算挂点再 TransformPoint
模型旋转/缩放组合极多，任何一处搞错就整体飞出去。
用户截图评价：**"越修越坏"、"怎么都脱离了"**。
**教训：直接在父节点局部空间给 localPosition，别碰网格顶点。**

### 错误 5：改了一个从未被调用的死代码
`VehicleModelBinder.WingUnderside` 是死代码（grep 只有定义没有调用），
我改了两轮才发现改的地方根本不起作用。
**教训：动手前先 grep 确认这个函数真的被调用。**

### 错误 6：一次改多处，无法归因
同时改位置、朝向、尺寸、挂点比例。用户说"还是不对"时无法定位。
**教训：一次只改一个变量，改完立刻让用户看一眼。**

### 错误 7（根本性）：**没有先"看见"再动手**
从头到尾我都没看过模型长什么样，全靠 `mesh.bounds` 和顶点切片猜。
用户两次提示"可以开blender看"、"多用用blender吧"，我才意识到问题。
**教训：几何问题先可视化，再算数。**
