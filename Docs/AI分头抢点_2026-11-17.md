## 2. 新逻辑（5 条）

### ① 按编号分摊

用 `UnitState.index` 对候选点取模，每台 AI 认领一个"自己的点"：

```csharp
int pickIdx = ((myIdx % list.Count) + list.Count) % list.Count;
var pick = list[pickIdx];
```

### ② 域匹配优先

船优先去海点（港口），坦克优先去陆点（城区/山地），飞机不挑：

```csharp
var same = new List<ZoneState>();
foreach (var z in cand)
    if (z.def.domain == _self.Def.domain) same.Add(z);
var list = same.Count > 0 ? same : cand;   // 没有同域的点才退回全部
```

**这一条很关键**：不这样的话炮艇会傻乎乎地往内陆山上开（根本开不上去）。

### ③ 排序保证分工一致

```csharp
sorted.Sort((a, b) => string.CompareOrdinal(a.def.id, b.def.id));
```

不排序的话 `List` 遍历顺序在不同实例上可能不同，同一队会算出互相矛盾的分工，等于没分。

### ④ 进点后散开（黄金角）

```csharp
float r = Mathf.Min(pick.def.bounds.width, pick.def.bounds.height) * 0.22f;
float ang = myIdx * 137.5f * Mathf.Deg2Rad;   // 黄金角，任意数量都散得匀
return new Vector3(c.x + Mathf.Cos(ang) * r, 0f, c.y + Mathf.Sin(ang) * r);
```

避免 5 台车挤在点正中央互相别车（`VehicleCollision` 会把它们弹开，看起来像抽风）。

### ⑤ 全占了就回防

所有点都是自己队的了 → 去离自己最近的己方点守，而不是傻站在最后一个点上。

## 5. 顺带发现的新问题（需要你注意）

### 🔴 滚雪球比想象中严重

这局敌方早早占满 3 点，我方 AI 被打崩（`我方3/死3`），**8 分钟就到 1500 赢了**。

原因：
- 3 个点全占 = 3 VP/s，8.3 分钟必赢
- 反雪球系数只加**金币**（落后方 ×1.3），**不加 VP**
- 金币买不到 VP，所以落后方拿再多钱也追不回来

**可选解法**（你定）：
1. 把 `积分上涨倍率` 调低（标准 ×1.0 → 较慢 ×0.75，占 3 点要 11 分钟）
2. 让反雪球也作用于 VP（落后方 VP 也 ×1.3）—— 但这会让"领先没意义"
3. 加"落后方占点 VP 加倍"这类机制

我倾向 **1**（已经在设置里给了档位，你自己调最省事），或者在结算里提示玩家可以调。

### 🟡 玩家不主动出击 = 白白挨打

这局我脚本里直到 400 多秒才让玩家出击，前期我方 3 台 AI 顶对面 5 台，直接崩。

**人肉玩的时候不会这样**（开局就会出击），所以这条不算 bug，只是提醒。
