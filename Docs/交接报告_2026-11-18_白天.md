## 3. 🔴 本轮踩的坑（按危害排序，都会让"改了没效果"）

### ① `airRollFollow` 必须是 1.0，不能是小数

用户："转了很多圈之后飞机歪斜了，应该与电脑边框永远平行"。

**根因是残差，不是漂移**：`camRoll = airRollFollow × 累计滚转角`。
滚一圈 360° 后飞机已回平飞（坡度 0），但相机被留在 `0.85 × 360 = 306° ≡ -54°`。
MCP 实测：**坡度 0°、相机 +54°**，飞机在画面里歪 54°；滚两圈歪 108°。

改成 1.0 后：滚 1 圈 / 3 圈（1080°）后相机都精确回 **0.00°**。

### ② 滚转增量的"轴"选错会攒歪（已修，但要知道为什么）

试过三种写法，只有第三种对：

| 写法 | 问题 |
|---|---|
| 把飞机 up 投影到**视线**平面求帧间夹角 | 投影平面自己在转 → 纯转弯也算成滚转（-0.77°/20° 转弯） |
| 四元数增量取**机头轴**分量 | 仰头 30° 时绕世界竖轴偏航 10°，在机头轴上分量 = 10°×sin30° = **5°**，但真实坡度变化是 **0°** → 每转一个弯攒几度 |
| ✅ **直接跟踪真实坡度角 + unwrap** | `_bankCont += Mathf.DeltaAngle(_bankCont, raw)`，对偏航/俯仰免疫 |

### ③ 自动改平的"触发条件"卡摇杆 = 回正慢 1.5 秒

用户："松手之后回正的时间太慢了，应该立刻做回正动作"。

原来条件里除了"没按 A/D"还有 `_airAimX < 0.25`，而摇杆回中速度 0.5/s，从满舵衰减到 0.25 要 **1.5 秒**。
那 1.5 秒飞机一动不动地歪着 —— 这就是"慢"。
**改法：只判"没按 A/D"，松开当帧就开始。**

### ④ 自动改平判据用错量（11-18 00:05 已修，但要记住为什么不能动上限）

旧代码 `Vector3.Angle(transform.up, Vector3.up)` 是**俯仰+侧倾的合成角**，
抬头 60~80° 爬升时它恒 >70（上限），自动改平**完全失效**。
现在用的是"绕机头轴的真实侧倾"（`SignedAngle(refUp, up, forward)`），所以放开上限是安全的。

### ⑤ 场景序列化覆盖脚本默认值

`airRollFollow` / `airLookDownDeg` / `airHeightFactor` / `airDistanceFactor` 存在场景里。
**改 `.cs` 的 `= xxxf` 对跑着的实例完全无效**。改法：
```
objects | get components | where $ is CameraFollow | set airRollFollow = 1; editor | call SaveScenes()
```

### ⑥ 测量相机的正确指标

```csharp
// ✅ 对：投影到视线平面再求角
float cr = Vector3.SignedAngle(Vector3.ProjectOnPlane(Vector3.up, cam.forward).normalized, cam.up, cam.forward);
// ❌ 错：Angle(cam.up, Vector3.up) 量的是**俯角**，恒在 15~21°，跟歪不歪无关
```

### ⑦ Play 模式下 `Time.timeScale` 可能是 0

开始封面没点"开始"时物理不跑（`deltaTime=0`），但相机用 `unscaledDeltaTime` **照跑**，
测出来一半真一半假。测之前先 `GameStartScreen.Begin()` + `Time.timeScale=1`。
