## 1. 改了什么

| # | 事项 | 文件 |
|---|---|---|
| 1 | 买不起的车卡右上角：`金币不足` → **`还差 N 金`**（N = 实际车价 − 可用金，含旧车回收） | `GarageScreen.cs` |
| 2 | 点买不起的车卡：浮字同样改成 **`还差 N 金`**（卡片本来就会抖动 + 拒绝音，仍然点不动） | `GarageScreen.cs` |
| 3 | 买不起提示条重写：**不再写"点左上「退出」回战场"**；改成倒计时 + **1.5 秒后自动升空观战** | `GarageScreen.cs` |

| 6 | `SoulCamera.CanUse()` **车库开着时返回 false**（原来返回 true，`Enter()` 会把车库当场关掉，和新的 1.5 秒缓冲打架） | `SoulCamera.cs` |
| 7 | **修相机 bug**：灵魂状态下从车库买了车，退出灵魂时不再把 `CameraFollow.target` 还原成 null | `SoulCamera.cs` |
| 8 | **修「退出」按钮**：中途没车又买得起时点退出原来会 `Restart()` **重开整局** | `GarageScreen.cs` + `MatchManager.HasDeployed` |

### 1.1 为什么第 6 条要改

车库开着时 `Time.timeScale = 0`，`SoulCamera.CanUse()` 原来不把车库当障碍：
倒计时还没走完，`SoulCamera.Update` 就自己 `Enter()` 了，**车库被当场关掉、1.5 秒缓冲等于没有**。
现在改成"车库开着时由车库自己决定何时升空"，两个入口不再抢同一件事。

### 1.2 第 7 条是真 bug（本轮顺手挖出来的）

灵魂视角进入时 `_follow.enabled = false`、`_savedTarget = 当时的 target`（没车时 = null）。
玩家在灵魂状态下从车库买了车，`SpawnUnit` 已经 `cf.target = 新车`；
关掉车库后 `SoulCamera.Exit()` 又无条件 `target = _savedTarget` → **新车开出去了，镜头却是死的**。
现在 `Exit()` 优先跟 `MatchManager.Player` 那台真车，没有才退回 `_savedTarget`。

### 1.3 第 8 条（顺手）

原来的分支：
```csharp
if (mm.Player != null)      { AbandonCurrentVehicle(); Close(); }
else if (!mm.CanAffordCheapest) Close();
else mm.Restart();          // ← 有车可买却主动放弃 → 重开整局
```
中途没车、买得起时点「退出」= **整局重开**（玩家只是想关掉车库）。
现在：
- 开局那次（`!mm.HasDeployed`）→ 才算"退出这一局回主菜单"
- 中途没车 → 不许空手走（走了就没有入口回车库），浮字提示「先选一台载具出击」

## 2. 现在的完整流程

```
金币够 ──► 车卡正常（「出击」/「点击出击 ›」）──► 点卡买车上场
金币不够
  ├─ 你有车  ──► 车卡灰掉 + 「还差 N 金」，点不动；仍可点「退出」/ 按 O 弃车升空
  └─ 你没车  ──► 提示条「买不起任何载具 · 还差 N 金 · 1.5 秒后自动升空观战」
                  ├─ 1.5 秒到 → 自动关库 + 升空（占点收入恢复）
                  ├─ 点「升空观战 ›」/ 按 O → 立刻
                  └─ 刚按 O 退出灵魂的那 6 秒内不自动升空（防"按 O 没反应"）
```

升空后金币继续涨；涨到买得起那一刻，`MatchManager` 自动弹车库（`_garageOpenForGold`，只弹一次）。

## 5. 补充（22:25）：用户报「数字全都对不上」

用户连拍两张换车界面截图：

| 图 | 金币格 | 六张卡「还差」反推出的可用金 | 差额 | 卡片上那句 |
|---|---|---|---|---|
| ① | 69 | 255−64 = 370−179 = 208−17 = **191** | 122 | 轻坦 162 → 显示「出击」 |
| ② | 29 | 267−157 = 389−279 = 219−109 = **110** | 81 | 轻坦 170 → 显示「还差 60」 |

`170 − 29 = 141`，玩家怎么算都不是 60。**数值没错，是界面把"判定用的钱"藏了**：
`afford` / `还差 N` 用的是 `SpendableGold = 金币 + 旧车回收`，而那笔回收只在开库时
飘 1.6 秒就消失。于是"金币 29 / 轻坦 170 / 还差 60"看起来就像经济系统坏了。

### 修法（本轮新增）

| # | 位置 | 改成 |
|---|---|---|
| 1 | 金币格 | 标题 **「可用金币」**，值 = `SpendableGold`，右边常驻小字 `29+70`（金币+回收明细） |
| 2 | 车库副标题 | `金币 29 + 旧车折价 70 = 可用 99 · 点新车＝回收旧车再扣车价`（新 `MatchManager.GarageSubtitle`，换车/手动开库两处共用） |
| 3 | 卡片「还差 N 金」 | 不变（本来就按可用金算，现在能自己验算了） |

验证（MCP Play，轻坦 140 / 金币压到 29）：

```
gold=29  tradeIn=70  spendable=99  轻坦价=140  还差=41      → 99 + 41 = 140 ✓
```
