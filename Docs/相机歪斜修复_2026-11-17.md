## 0. 截图里看到了什么

地平线**斜着**、整个世界跟着转，而飞机本身也在倾斜。

---

## 1. 两个原因

### 原因 ①：相机跟着飞机滚转 85%

`CameraFollow.airRollFollow` 控制"镜头跟着飞机滚多少"：
- `1.0` = 完全跟随（飞机压杆，地平线跟着斜）
- `0` = 永远水平

原来是 **0.85** —— 飞机压 45° 杆，镜头就跟着滚 38°。**整个画面是歪的**。

### 原因 ②（更隐蔽）：飞机超过 40° 就永不改平

```csharp
// 旧代码
if (tilt > 0.4f && tilt < airAutoLevelMaxBank)   // airAutoLevelMaxBank = 40
{
    // 自动把机翼摆平
}
```

**倾斜超过 40° 时这段逻辑完全失效**，飞机就一直斜着飞。

而斜着飞时 `bankSin ≠ 0` 会持续产生偏航（`airBankTurnRate = 42°`）——
于是变成「一直歪着转圈」，怎么飞都是斜的。这才是"总有一种歪歪斜斜"的来源。

---

## 2. 🔴 最坑的一点：**场景覆盖了代码默认值**

我把 `airRollFollow` 从 0.85 改到 0.6、又改到 0.12，**两次都没生效**。

原因：`Map_Battlefield.unity` 里序列化了这个字段：

```yaml
airRollFollow: 0.85
```

Unity 的规则是**场景里存的值覆盖 C# 默认值**。改脚本里的 `= 0.12f` 对已存在的组件实例毫无作用。

**验证方法**：运行时打印真实值
```
改代码后运行时读到：airRollFollow = 0.85   ← 还是旧值
```

**修法**：用 MCP 直接改场景里的组件，再存盘：
```
objects | get components | where $ is CameraFollow | set airRollFollow = 0.12
editor | call SaveScenes()
```

改完确认场景文件里是 `airRollFollow: 0.12`。

> 同样类型的坑还有两次：`DataSeeder` 会覆盖 `.asset`；
> 现在这一个：**场景覆盖脚本默认值**。以后改任何 `[public]` 参数，
> 都要先确认它有没有被场景/prefab 序列化。

## 3. 改了什么

| 项 | 旧 | 新 | 位置 |
|---|---|---|---|
| **airRollFollow** | 0.85 | **0.12** | **场景**（不是脚本！） |
| airAutoLevelMaxBank | 40 | **85** | 脚本 |
| airAutoLevelRate | 3 | **4.5** | 脚本 |
| 自动改平插值 | `Slerp(rot, level, 3f*dt)` | `Slerp(rot, level, 1-e^(-4.5·dt))` | 脚本（顺带修成帧率无关） |

**85° 上限**意味着：只要松开 A/D，飞机几乎在任何姿态下都会自己摆平。
桶滚/倒飞靠"按住 A/D"实现，不受影响。

### 自动改平

```

```

### 相机不歪

```
平飞时：相机真实滚转 = 0.0°     ✅ 地平线完全水平
压杆 45° 时：相机真实滚转 = 0.0° ✅ 飞机倾斜但世界不歪
```

截图对比（`work/shots10/banked_view.png`）：
飞机明显压着 45° 杆，但**地平线是水平的** —— 这正是飞行游戏该有的样子。

### 🔴 测量方法的一个坑

我一开始用 `Vector3.Angle(cam.up, Vector3.up)` 来测"歪没歪"，
读出 15°、21°，看着像有问题，其实是**俯角**（相机要往下看飞机），不是滚转。

**正确的测法**是把世界 up 投影到画面平面，再和相机 up 求绕视线的夹角：
```csharp
Vector3 refUp = Vector3.ProjectOnPlane(Vector3.up, cam.transform.forward).normalized;
float roll = Vector3.SignedAngle(refUp, cam.transform.up, cam.transform.forward);
```
