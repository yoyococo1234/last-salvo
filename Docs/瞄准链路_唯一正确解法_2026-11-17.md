## 0. 一句话

开镜瞄准 = **三件独立的事**，任何一件出错都会偏。改之前先分清改的是哪一件，**机位和视线必须成对使用，只改一半必然坏**。

| 环节 | 代码位置 | 职责 |
|---|---|---|
| ① 炮管指哪 | `VehiclePhysics.AimDirectLocal(relYaw, pitch, turn)` | 锁定后把目标方向**转进船体坐标系**再拆成炮塔偏航+炮管俯仰 |
| ② 镜心看哪 | `CameraFollow` 的 `_scoped` 分支 | 机位在炮塔上方后撤；视线**从实际机位看向炮管轴线上的命中点** |
| ③ 框/弹道锚点 | `LockOnSystem.AimAnchor(v)` | 统一用"排除 `MG_` 的渲染包围盒中心" |

## 1. ② 的正确写法（核心，别改）

```csharp
// ---- 机位：炮塔上方 + 沿视线水平后撤 ----
Vector3 camPos = turretPivot - back * backDist;
camPos.y = turretTopY + 0.42f;
camPos = LiftCameraOutOfSelf(camPos, lookDirS, target);      // 防钻进自己车体
float groundS = Mathf.Max(BattlefieldTerrain.SampleHeight(camPos.x, camPos.z),
                          BattlefieldTerrain.WaterLevel) + 1.2f;
if (camPos.y < groundS) camPos.y = groundS;
transform.position = Vector3.Lerp(transform.position, camPos, 16f * Time.unscaledDeltaTime);

// ---- 视线：从【实际机位】看向【炮管轴线上的命中点】----
Vector3 muzzlePosS = vp.GetMuzzlePosition();
Vector3 barrelPt = muzzlePosS + lookDirS * 1500f;
if (Physics.Raycast(muzzlePosS + lookDirS * 5f, lookDirS, out var hitS, 3000f,
                    ~0, QueryTriggerInteraction.Ignore)
    && Vector3.Distance(muzzlePosS, hitS.point) > 40f)
    barrelPt = hitS.point;

Vector3 lookAtS = barrelPt;                    // ★★★ 不是 lookDirS！★★★
transform.rotation = Quaternion.Slerp(transform.rotation,
    Quaternion.LookRotation(lookAtS - transform.position), 16f * Time.unscaledDeltaTime);
```

### 为什么必须这样（几何）

机位在炮塔上方，**不在炮管轴线上**（炮艇差 2~4 m）。如果视线直接用 `lookDirS`：

```
镜心方向 ∥ 炮管方向  → 两条平行线，间距 2~4 m
350 m 处：镜心比真实弹着点高 0.5°（14° 视野 ≈ 45 px）
```

改成"看向炮管轴线上的命中点"后，镜心**必然**落在弹着点上（因为屏幕中心就是视线的方向）。

### 11-12 与 11-17 的验收值（同一场景，炮艇，开镜 fov=14）

| 距离 | 炮管→目标 | 镜心→目标 |
|---|---|---|
| 400 m | 0.13°（11-12）/ **0.14°**（11-17 恢复后） | 0.12° / **0.14°** |

> 800 m 以后出现的 0.4~0.5° **不是误差**，是弹道下坠补偿
> （800 m/s 弹速、1100 m 飞 1.4 s，掉 9.3 m ≈ 0.48°）。炮管本来就该比视线高一点。

## 2. 🔴 11-17 踩过的坑（三个，都会让准星"有时候出去"）

### 坑 ① 只改机位、忘了视线（最致命）

11-17 凌晨把机位改成"相机与炮管同轴"（沿 `-lookDir` 后撤），**同时**把视线从 `barrelPt`
换成了 `lookDirS`。上午又改成"相机沿轴线前推到船外"，视线仍是 `lookDirS`。

**结果：`barrelPt` 这个补偿没了，准星重新偏掉。用户连报两轮"还是不对"。**

> **教训：② 是一个整体（机位 + 视线），不能只改其中一半。**

### 坑 ② 开镜隐藏炮塔 → 机位每帧自反馈抖动（"有时候还是会出去"）

加了"开镜隐藏炮塔渲染器"之后，`CameraFollow` 里算机位高度/后退距离的代码是：

```csharp
foreach (var r in vp.turretBone.GetComponentsInChildren<Renderer>())
{
    if (!r.enabled) continue;     // ❌ 错的
    ...
}
```

于是形成**每帧死循环**：

```
第 N 帧：炮塔渲染器开着 → turretTopY=9.31, turretSpan=6.13 → 相机就位
        → 然后隐藏炮塔渲染器（SetTurretRenderersVisible）
第 N+1 帧：渲染器全关 → 上面全跳过 → any=false
        → turretTopY 退回 turretPivot.y+1 = 7.78
        → turretSpan 退回默认 2.00
        → 机位高度跳 1.52 m、后退距离跳 4.13 m → 准星飞出船外
```

**MCP 实测（炮艇开镜后）**：

| 参数 | 看 enabled（错） | 不看 enabled（对） | 跳变量 |
|---|---|---|---|
| `turretTopY` | 7.78 | 9.31 | **1.52 m** |
| `turretSpan` | 2.00 | 6.13 | **4.13 m** |

**修法：算包围盒一律不看 `enabled`。**
`Renderer.bounds` 在 `enabled=false` 时**依然有效**——机位几何只应由"炮塔有多大"决定，
不能由"这一帧渲染器开没开"决定。

```csharp
// ✅ 正确
foreach (var r in vp.turretBone.GetComponentsInChildren<Renderer>(true))
{
    if (r == null) continue;
    if (r is ParticleSystemRenderer || r is TrailRenderer || r is LineRenderer) continue;
    // 不检查 r.enabled！
    ...
}
```

**同一处也要改 `LockOnSystem.VisualCenter`**（锁定锚点），否则船在开镜/不开镜两种状态下
"视觉中心"会不同，锁定框跟着跳。

### 坑 ③ 锁定框被两处代码各画一遍

- `LockOnSystem.OnGUI` —— 裸屏幕像素，**不套 `GUI.matrix`**
- `MatchHUD.DrawLockCrosshair` —— 虚拟画布坐标（`_scale` 缩放）+ 平滑插值

两个 `OnGUI` 在同一帧跑，`GUI.matrix` 是**全局状态**，谁后画谁被缩放。
MCP 实测同一锚点：一处算到屏幕 y=763，另一处 y=572，**差 190 px**。

**修法：只留 `MatchHUD.DrawLockCrosshair`。** `LockOnSystem` 只保留
「目标跑出画面时的边缘箭头」和距离文字，**不画框**。

## 3. 目标跑出画面时不要画框

`WorldToScreenPoint` 在目标跑到画面外时会给出**极夸张的坐标**
（MCP 实测：目标 150 m 外偏 0° 时 `x = -5984`，屏幕只有 2560 宽）。
不检查范围就会把框画到屏幕角落的"空气里"（用户原话："锁定框飘到左上角的空气"）。

```csharp
bool onScreen = sp2.x > 0f && sp2.x < w && sp2.y > 0f && sp2.y < h;
if (!onScreen)
{
    // 不画框，只在屏幕边缘画一个方向箭头 + "目标在视野外 XXX m"
    return;
}
```

## 4. 水面高度：`CrestOcean.y` 必须等于 `WaterLevel`

**11-16 的遗漏**：`BattlefieldTerrain.WaterLevel` 从 `-6.6667` 抬到 `+4`（+10.67 m），
但场景里 `CrestOcean` 的 `m_LocalPosition.y` 还停在 `-6.6667`。

后果链（MCP 实测）：

```
SeaBuoyancy 采样 Crest 波高(≈-6.67)，船 root 在 4.3
  → heave = (波高 - root) = -11
  → VisualRock（模型+炮塔+炮口）被往下拽 11 m
  → 命中盒挂在 root 上没跟着沉 → 命中盒与可见模型错开 11.35 m
  → "打空气扣血"（你看到的船在 y≈-4.4，炮弹撞的盒在 y≈6.9）
  → 炮口沉到水下 → CameraFollow 的 clamp 把相机强行抬高 → 准星偏
```

**已修**：场景 `Map_Battlefield.unity` 里 `CrestOcean`（fileID `1041117378`）的
`m_LocalPosition.y` 改成 **4**。改完 `heave` 从 -10.99 → -0.43，命中盒与模型差 11.08 → 0.42 m。

> ⚠️ 改这个之前先想清楚：它影响**海岸线视觉**（水面抬高 10.67 m）。
> 实测多淹面积约 1.6%（32.2% → 33.8%），用户确认可接受。

## 5. 炮弹是纯物理，不是制导

2026-11-16 23:20 曾对锁定目标无条件加**制导 + 6 m 近炸**（`_homingTurn = 360°/s`），
炮弹会拐弯追人 —— 用户反馈"不像真的子弹了"。

**现在是纯物理弹道**：`Projectile.EnableHoming = false`（默认关）。
锁定只负责**把炮口算准**（`AimPointFor` 做提前量 + `BallisticDir` 做弹道解算），
打出去之后按初速 + 重力飞，**打不中就是打不中**。

只有 `ammo.id` 含 `"missile"` 的弹药才走制导。

## 6. 验证脚本（照抄，别自己编）

```csharp
// 1) 进 Play → 开始 → 出击炮艇
var gs = FindFirstObjectByType<GameStartScreen>(); if (!GameStartScreen.Started) gs.Begin();
MatchManager.Instance.DeployPlayer(炮艇Def);
FindFirstObjectByType<GarageScreen>().Close();

// 2) 冻一台敌船当靶子（关 AI + VehiclePhysics + VehicleCollision，否则下一帧自己开走）
enemy.GetComponent<VehicleAI>().enabled = false;
enemy.GetComponent<VehiclePhysics>().enabled = false;
enemy.GetComponent<VehicleCollision>().enabled = false;
enemy.transform.position = player.transform.position + player.transform.forward * 400f;
LockOnSystem.DebugTarget = enemy;                                        // 免按 Ctrl
Camera.main.GetComponent<CameraFollow>().forceScopeForTest = true;      // 免按 Shift
await Delay(2000);

// 3) 两个指标（读**真实**相机，不要手算 camPos 再瞬移过去测！）
var vp = player.GetComponent<VehiclePhysics>();
var cam = Camera.main;
Vector3 aim = LockOnSystem.AimPointFor(player);
Vector3.Angle(vp.GetMuzzleForward(), aim - vp.GetMuzzlePosition());   // 炮管→目标，应 ≤0.2° @400m
Vector3.Angle(cam.transform.forward, aim - cam.transform.position);    // 镜心→目标，应 ≤0.2° @400m

// 4) 屏幕投影：准星是否落在船体上
Vector3 anchor = LockOnSystem.AimAnchor(enemy);
Vector3 sp = cam.WorldToScreenPoint(anchor);
var bc = enemy.GetComponent<BoxCollider>();
Vector3 spTop = cam.WorldToScreenPoint(new Vector3(anchor.x, bc.bounds.max.y, anchor.z));
Vector3 spBot = cam.WorldToScreenPoint(new Vector3(anchor.x, bc.bounds.min.y, anchor.z));
bool ok = Screen.height*0.5f >= spBot.y && Screen.height*0.5f <= spTop.y;   // 应为 true

// 5) 稳定性：开镜中连测 5 帧，相机位置必须**完全不动**
for (int i = 0; i < 5; i++) { Debug.Log(cam.transform.position); await Delay(50); }
```

> **⚠️ 验证纪律（11-17 检讨）**：不要"手算一个 camPos → 把相机瞬移过去 → 测出 0.0 px → 宣布修好"。
> 真实运行时相机是 `Lerp`/`Slerp` **平滑追过去**的，手算的位置和玩家看到的画面不是一回事。
> **必须读真实运行中的相机**，并且测**多帧稳定性**（坑 ② 就是只有连续多帧才暴露）。
